## 继续推进：数据集源（Zenodo / HuggingFace）

上一轮列的待办里，除前端题录导入（10-16 已完成 `cb66f5f`）外，
本轮做的是**数据集枢纽**。

### 为什么要做
论文源（OpenAlex/Crossref/arxiv）只能找到「文献」。但材料实验的关键数据
——SCAPS 模拟输出、DFT 计算结果、XRD 原始谱、电池循环数据——大量发布在
公开数据集仓库而非论文里。此前这条路是断的。

### 落地
新增 `matlens_kit/rag/datasets.py`：
- Zenodo 主源（实测稳定，开放许可常为 CC-BY）
- HuggingFace 备源（实测国内直连超时 WinError 10060 → 默认不勾选）
- 带许可证 / 文件清单 / 总体积；`fetch_record_files` 查完整文件列表
- **只取元数据不自动下载**（数据集动辄上百 MB，应由用户显式决定）

端点：`/api/kb/datasets/{sources,search,import}` + `/{id}/files`

### ⚠️ 踩的五个坑（都是实测出来的）
1. **User-Agent 含中文 → UnicodeEncodeError**。HTTP 头必须 latin-1 可编码。
   一开始 UA 写「MatLens/0.1 (材料化学研究工具)」直接炸。
2. **Zenodo 上论文远多于数据集**：「solid oxide fuel cell」命中 49 万，
   前 5 条全是 journal article。必须用**服务端** `type=dataset` 参数过滤，
   客户端滤会漏 subtype 变体还白跑一趟。
3. **`type=dataset` 里仍混着无文件的论文补充材料记录**：DOI 是出版商的
   （10.1002/xxx）、`files=[]`。判据应是**有无实际文件**，不是 type 字段 ——
   否则挤占检索结果且用户根本拿不到数据。
4. **空查询会让 Zenodo 返回「最近上传的任意数据集」**（ok=True 但内容与
   关键词无关）→ 直接拒绝。
5. **HTML 实体要用 html.unescape**：描述里常见 `&aring;` 这类命名实体，
   漏解会让 `&xxx;` 字面量进 prompt。

### 实测质量
三组材料关键词命中全是真数据集：
- SCAPS-1D Parameter Database for Photovoltaic Materials（2 文件）
- PyBaMM-Simulated Lithium-Ion Battery Degradation（10 文件 4.2 GB）
- Powder X-ray diffraction patterns（XRD 谱图）
均带 DOI + CC-BY-4.0 + 真实文件清单。

## 数据集检索前端界面（`f01492c`）

### 新增
- `design/prototype/js/kb_dataset.js`：检索 / 卡片 / 文件清单浮层 / 勾选导入 / 复制引用
- `index.html`：知识库页第三个模式「数据集」（与「本地库」「云端 API」平级）
- `kb.js`：`switchKbMode` 支持 dataset；`loadKb` 模式分支调整

### 交互要点
- 卡片显示**许可证徽章**（CC-BY 蓝 / CC0 绿）、文件数、总体积、描述
- 「文件清单」浮层列完整文件与体积 + 直链，并明确写
  **MatLens 不会自动下载**（数据集动辄上百 MB，应由用户显式决定）
- 「复制引用」输出 BibTeX `@dataset` 条目，可直接粘进 LaTeX / Zotero

### ⚠️ 修了两个真问题
1. **数据集模式左栏沿用了云端模式的学术 API 目录**（OpenAlex/Crossref…）
   —— 用户在「数据集」标签下看到文献源，完全是另一回事。
   新增 `renderDatasetSrcList()`。
2. **`loadKb` 在云端/数据集模式下提前 return**，导致 `S.kb` 与 `doc-count`
   不刷新：数据集导入后文献数纹丝不动，用户以为没导入成功。
   改为模式分支也加载本地库数据（S.kb + loadDocs + renderStoreInfo）。

### 诊断陷阱（我自己踩了）
「导入后计数没变」我一开始当成 bug 查了半天 —— 实际是**底层按文件名去重**，
重复导入同一条被跳过，是正确行为。测「计数会变」必须换一条新数据。
同理：改了后端代码但**服务没重启**，界面仍显示旧行为（0 文件的记录还在）。
