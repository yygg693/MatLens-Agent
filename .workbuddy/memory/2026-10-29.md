## 源健康自检与面板（`f8863ea`，+23 测试）

### 解决什么
此前只能「**用的时候才知道**」某个源挂了 —— 用户勾 5 个源去搜，结果少了一半
却不知道为什么少。自检让状态主动可见。

### 五档状态
`ok` / `degraded`（连通但探测词无命中）/ `down` / `need_key` / `off`

**need_key 与 down 必须分开**：没配密钥不是源坏了，是用户还没配置。
混为一谈会让用户以为源方挂了。

**失败原因分类**：配额耗尽 / 超时 / DNS / TLS / robots / 需密钥 ——
各类处置方式不同，只说「不可用」等于没说。

### 实测结果（这正是用户此前无法自己发现的）
- **DBLP**：反爬验证拦截
- **Semantic Scholar**：429 限流（隔一会儿又恢复 → 状态确实动态）
- **万方 / AMiner**：未配置密钥
- OpenAlex / Crossref / arXiv / Europe PMC / PubMed / Zenodo：正常

### ⚠️ 性能踩坑：27 秒 → 10.4 秒
三个原因叠加：
1. 并发数 6 → 10
2. **免重试模式**：`_http_get` 的 `retries=1` 会把 5s 超时翻倍成 10.8s。
   给 `scholarly` / `datasets` 加了 `_set_probe_mode()`，自检期间关掉重试
   （真实检索仍应重试 —— 那时多花几秒换来结果更值）。
3. **默认关闭的源不探测**：HuggingFace 的失败是 **DNS 解析超时**
   （WinError 10060，socket timeout 管不了），挂 10.9s 会把整体从 7s 拖到 17s。

### 缓存必须有
10 分钟 TTL。自检是网络操作，每次开页面都探会拖慢首屏、白耗免费 API 配额。
用户点「立即检测」才 force 刷新。

## crawl4ai L3 动态渲染（`75f5276`，+14 测试）

用户指定顺序：先 crawl4ai，再缓存统计。

### ⚠️ 发现的真问题：L3 从未被调用过
`web_fetcher._has_crawl4ai()` 只做**检测**，实际抓取路径**从未调用** crawl4ai
—— 文档里「L3 装了自动用」是**空头承诺**。

### 实测对照（同一个 JS 页面）
| 层级 | 结果 |
|---|---|
| L2 静态抽取 | **15 字**「加载中...」（JS 页面典型症状） |
| L3 动态渲染 | **104 字**完整正文（JS 生成的标题 + 两段内容） |

### 安装
- crawl4ai 0.9.5 装到 `vendor/pylibs`（沿用项目既有机制，不污染 .venv）
- 浏览器装 **patchright** 对应的 chromium 1248（crawl4ai 走 patchright 不是 playwright）
- ⚠️ 装 patchright 时会把旧的 chromium-1208 删掉 → 我的浏览器测试脚本要重装 1208

### ⚠️ 七个坑（全是「静默失败」，不报错）
1. **配置要用对象**（BrowserConfig / CrawlerRunConfig），传 dict 静默失效
2. **page_timeout / wait_for / js_code 都在 CrawlerRunConfig**，不在 BrowserConfig
3. **UndetectedAdapter 要挂 strategy 上** —— 传给 AsyncWebCrawler 会被塞进
   **kwargs 静默忽略，结果仍走默认 PlaywrightAdapter（要求另一套浏览器版本）
4. **js_code 不是等待语义** —— 实测传了也拿不到渲染后内容
5. **wait_for 是「任一匹配即返回」** —— `css:body` / `css:body *` 都立刻返回，
   拿到的还是渲染前内容；只有具体内容元素才等得住，但选择器因站点而异无法通用
   → 改用 `delay_before_return_html=3.0` 兜底
6. **正文长度阈值不能定 200** —— 渲染后正文长度因页面而异（几十字也正常），
   实测 28 字被误判为失败。降到 40 字 + 内容判据（占位文本检测）
7. **触发条件必须含「正文过短」** —— JS 页面静态 HTML 里常有占位文字（15 字），
   **非空但无内容**，只判 `not text` 会漏掉

### 实现要点
- 只作**兜底**：静态正文 < 120 字才升级，不影响 arXiv/Nature 这类静态页面
- 失败静默降级回 L2，绝不影响既有抓取路径

- 无遗忘/衰减/去重/冲突仲裁机制；`mem_trim.py` 只做 prompt token 裁剪

### 核心结论

- **不要大重构**：arXiv:2607.16848 用科学论文语料（81+252 篇）实测 8 套记忆系统，**固定检索预算后复杂架构优势统计上消失**（Simple RAG 7.25 / Theoria 7.19 / Mem0 6.97，CI 互相覆盖）；Graphiti 原生领先（8.04）完全由每次查询返回 2.55M 字符造成，限预算后掉到 5.27
- **BM25 在材料语料上价值高**：同论文 PTr 语料 BM25 单独贡献最高 +0.5 分；dense 检索漏掉精确字符串案例 5.0 → 10.0
- **Hindsight 在论文场景不适配**：其设计预期 conversation exchanges，300KB ingest cap 拒收 3 篇论文，服务端 recall cap 固定 ~19K 字符不响应预算参数
- **人类记忆映射要点**：遗忘曲线→时间衰减降权；提取练习效应→记忆确认 UI（性价比最高）；再巩固（Nader 2000）→检索触发的修改必须 append-only；两系统互补（McClelland 1995）→原文层/提炼层双层；编码特异性→记录编码情境，因纯稠密检索只用了语义一条线索
- **P0 四项**：记忆中心前端（2-3天，原型移植）/ 混合检索+RRF（3-5天）/ 冲突仲裁+版本化（3-5天）/ 溯源安全加固（2-3天）

### 顺手修掉的依赖管理欠账（改名遗漏的连锁反应）

本轮装依赖时发现仓库的 `package.json` / `package-lock.json` 与 `node_modules` 三方脱节，且脱节会**直接破坏 `npm ci`**。

**取证**：
- `apps/desktop/package.json`（HEAD）声明 `"name": "hermes"`、依赖 `"@hermes/shared": "file:../shared"`
- 但 `apps/shared/package.json` 的真实包名是 **`@matlens/shared`**，桌面端**所有代码**都 import `@matlens/shared`
- `package-lock.json`（HEAD）里 `apps/desktop` 条目写的是 `"name": "matlens"`、依赖 `"@matlens/shared"` → **与 package.json 恰好不一致**

结论：全仓 Hermes→MatLens 改名时改了 lock、漏了 `apps/desktop/package.json`（或者反过来被回退）。94 个依赖的版本范围两边完全一致，差异只有 name 与一个依赖名两处字符串。

**修法（只改 2 个字符串，方向与 lock 对齐）**：
- `apps/desktop/package.json`：`name` → `"matlens"`；`"@hermes/shared"` → `"@matlens/shared"`
- 安全性已验证：打包产物名由 `build.productName`/`artifactName`/`executableName` 决定，**与顶层 `name` 字段无关**；全仓库无脚本引用顶层 `name`；`productName`/`executableName` 保持 "Hermes" 不变，装出来的仍是 Hermes.exe

**修完的一致性校验**：`apps/desktop` 的 name 一致、94 个依赖零差异、无缺依赖、无多余依赖 → 与 HEAD lock 完全对齐。

**回退的两处自作主张**（`npm install` 引入，非本轮需求）：
1. 根 `package.json` 的精确版本被 npm 改写成 `^`（`@eslint/js`/`globals`/`typescript-eslint`/`perfectionist`）→ 已还原成仓库的 pin 精确版本风格，diff 归零
2. 在 `apps/desktop` 与 `web` 子包重复声明 eslint 依赖 → **纯冗余**：monorepo 根 `devDependencies` 本来就有 `@eslint/js`/`perfectionist`/`react-hooks`/`unused-imports`/`globals`/`typescript-eslint`，且根 `node_modules` 里 `eslint-plugin-react-refresh` 也在，子包 eslint 配置靠 workspace 提升机制向上解析即可 → 已 `git checkout` 回退子包声明

**package-lock.json 的坑**：本机 npm 配的是 npmmirror 镜像源，`npm install --package-lock-only` 会把 lock 里所有 `resolved` 改写成 `registry.npmmirror.com`，还会把本机装着的旧 `hermes-parser`/`hermes-estree` 写进去（仓库 lock 是 `matlens-parser`）—— 这类镜像源污染 + 本机状态快照**不该进仓库**，已 `git checkout package-lock.json` 还原，改用改 package.json 去对齐既有 lock 的方式解决。
