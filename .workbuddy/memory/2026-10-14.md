# 第四轮：科研绘图链（第一级 + 第二级）

## 决策依据：为什么不做"AI 生图"

查证结论：**DeepSeek V4 全系（含 V4-Pro）没有图像生成端点**，官方 API 无此能力；2026 路线图有规划但未落地。V4.1-Flash 支持图像**理解**（输入），但理解≠生成。

**更重要的判断**：即使有生图模型，对科研数据图也**无用甚至有害**——数据图必须数值可复现（审稿人能对照原始数据重新画出来），扩散模型产出的是像素插值、无数据溯源，在学术上等同造假。正确形态是**代码绘图 + 专业算法库**（GPT-Image2 类工具的边界也是"涉及真实坐标/置信区间时必须由代码绘图接管"）。

GitHub 参考（借鉴价值排序）：CoDA（Google, ICLR 2026，8 Agent 四阶段 + VisualEvaluator 阈值重做）、MatPlotAgent（清华，三阶段 + MatPlotBench 100 用例）。领域库：`impedance.py`（ECS Hack Week 起源，JOSS 收录）、`pymatgen`（Materials Project 官方）。

## 一级：7 种数据图谱系（`fig_kit.py` + `fig_schemes.py`）

改动前`fig_gen` 的 data 类图**一律 skipped**，v7 的 8 图注只有 1 张能画。现在按谱系从 `experimental_data.tables` 取数绘制：

| 谱系 | 产出指标 |
|---|---|
| `sigma_t` / `arrhenius` | 组分数 / **Ea(eV) + R²** |
| `density_shrink` / `iv_ip` | 组数 / **峰值功率密度** |

## 二级：EIS 专业库（`fig_eis.py`，impedance.py 1.7.1）

三档等效电路自动选优：`R0-p(R1,CPE_1)-p(R2,CPE_2)` / `R0-p(R1,CPE_1)` / `R0-R1-R2`。拟合实测：合成 R0=0.12、n=0.85 数据 → `R0=0.11998`、`CPE exponent=0.8483`、**残差 0.0003**。

**impedance 1.7.x API 踩坑（4条，都写进文档了）**：
1. 元件语法是 `R0-p(R1,CPE_1)`（串联 `-`、并联 `-p(...)`），**不是**逗号分隔（`R0,R1,R2` 会把`R0` 当常数）
2. 参数名用 `get_param_names()`，且返回**元组** `(names, units)` —— 直接 `list()` 得嵌套列表导致参数 dict 全空
3. `parameters_` 在 `fit()` 前是 `None`
4. 绘图模块是 `impedance.visualization`（**不是** `impedance.plotting`，1.7 已移除）

降级语义：库缺失/失败 → 退回纯散点并如实标注 `library="matplotlib (impedance.py 不可用)"`。

## 踩坑：多表误聚合（差一条就画出假数据）

σ–T / Arrhenius 要把"所有组分的表"聚到一张图。σ_e–pO₂ 表被误拉进来——`pO₂ (atm)` 列名含 `t` 被当温度列，且 `1e-25~1e-18` 逐值看都"落在 [-50,2000] 内"（都≈0）骗过区间检查，凭空多出一条 **Ea=0.00 eV 的假曲线**。

修复用了**四重物理约束**：跨度 1~2500（**下限**是关键，上限拦不住极小跨度）、起点 |min|≤2000、单调递增/减、相邻间距比 <100。同时把 `to_xy` 的列匹配改为**精确相等优先、子串兜底**（原来单字符关键词 `t`/`i`/`j` 会匹配任意含该字母的列名，如 `σ_e (S·cm⁻¹)` 命中单位里的 `t`）。
