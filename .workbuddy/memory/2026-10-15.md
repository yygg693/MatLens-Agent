## A3：chip 分组与层级

**语义问题**：模型/上下文/审批/工作区四个 chip 功能等价地平铺，但实际分两类——

- **配置**（模型 / 工作区）= 我"设定"的，常驻低对比
- **状态**（上下文 / 审批）= 系统"报"的，**需要一眼看出好坏**

实现：细分隔线 `.chip-sep` 分组 + 状态类加 `.chip-led` **色点**（替代 emoji——emoji 表情固定，看不出状态好坏）。

色点分级：
- 上下文：<60% 绿 / 60~85% 黄 + `alarm` 类 / >85% 红 + `alarm-danger` 类（异常时整颗 chip 提亮，扫视即可发现）
- 审批：开启=绿点（有防护）/ 关闭=灰点

DOM 顺序也调整了：模型 → 工作区 → 分隔线 → 上下文 → 审批。

## chat.js 拆分：1190 → 532 行（-55%）

### 拆分策略：先做依赖分析，不盲目抽

写脚本分析了 40 个顶层函数的内部调用关系，找出**零内部依赖**的函数，据此选最安全的抽离点。结果 19 个面板/工具函数绝大多数零依赖。

### 最终结构

| 文件 | 行数 | 职责 |
|---|---|---|
| `chat.js` | 532 | **SSE 主循环**（sendMsg / startStream / onChatEvent / stop）+ 输入区 + @工具选择器 |
| `chat_toolcards.js` | 419 | 工具结果渲染 / 执行计划卡 / 工具卡 / 审批卡 / 执行日志侧栏 |
| `chat_panels.js` | 308 | 模型 / 上下文 / 审批 / 工作区四个面板 |
| `chat_ui.js` | 224 | 侧栏折叠 / 引导卡 / 状态图标 / 字数提示（本轮前面新建） |

### 关键决策：依赖注入解循环

`chat_toolcards.js` 需要 chat.js 的 4 个东西（`_autoScroll` / `_flushStreamRender` / `setBusy` / 执行日志跳转）。直接 import 会造成 **ESM 循环依赖**（拿到 undefined）。

解法：`injectChatDeps({...})` 显式注入，未注入时退化为安全空操作（模块可独立加载、不因顺序出错）。注入点在 `initInputTools()` 而非模块顶层——**显式延后更清晰，也避免将来有人把回调改成 const 箭头函数时静默失效**。

### `stop()` 特意移回主循环

它属于 SSE 生命周期控制，与 sendMsg / startStream 同源，放在工具卡模块不合职责。拆完发现 main.js 报 `does not provide an export named 'stop'` 才发现——**这正说明拆分后必须跑真实浏览器验证，静态检查发现不了**。

### 验证

浏览器实测：window.ML 8 键、模型/上下文面板正常打开、引导卡在、**停止生成实测可用**（发消息→点停止→状态回"就绪"）、console 零错误。全量回归 295 passed。

**教训**：ESM 拆分后 `_bindChatGlobals2` / `openExecLog` / `closeExecLog` 的导入归属全部变了，main.js 必须同步改两处 import块。这类错误只有真跑才能发现。

## Agent 抓取能力升级（web_fetcher）

用户要「无敌爬取能力 + 反追踪能力」，并要求上 GitHub 找大神项目。

### ⚠️ 合规边界（已明确拒绝并写进代码）
**不做**：undetected-chromedriver / playwright-stealth 指纹伪装、验证码 OCR 与滑块破解、付费墙 cookie 注入、代理池轮换规避封禁、伪造 Referer/登录态绕过机构访问控制。
理由：知网协议禁止自动化抓取；出版商反爬是站点明确意愿；**学术工具的长期可持续性来自被当成正当工具对待**——伪装 UA 被识破后封的是整个学校/机构 IP 段，反而损害同校师生。
落地方式：`web_fetcher.REFUSED_TECHNIQUES` 常量写死清单；`fetch()` 签名里**没有** stealth/headless/proxy/bypass/cookie 参数（有测试守卫 `test_no_stealth_switch_in_public_api`）。

### 「隐私保护」的正当实现
- UA 如实标识 `MatLens/0.1 (+github.com/yygg693/matlens; mailto:…)`，站点方能联系到我们
- 遵守 robots.txt（urllib.robotparser，带缓存）—— **实测拦下 MDPI 与 CNKI 检索路径**
- 同域限速 1.5s、同域串行、最多 3 域并发
- 磁盘缓存 `~/.matlens/fetch_cache/`（默认 24h）
- 失败给**可执行 hint**（401/403 → 指向 Unpaywall 找 OA；429 → 降频；robots 拒绝 → 人工导出题录），而不是让 Agent 死磕重试

## 追加：明令禁止名单 + 真正的反追踪（同日 23:0x）

⚠️ **用户澄清了两处误解**：
1. 「反追踪」= 抓取时**保护我们自己的 IP/身份不被对方追踪**，不是让我去做 stealth 伪装。之前理解偏了。
2. 「明令禁止知网」= 直接在代码里硬拦，不要只是文字说明。

### 明令禁止名单（BLOCKED_SITES，8 个域）
知网(cnki.net/cnki.com.cn)、维普(cqvip.com/cqvip.cn)、超星/读秀(chaoxing.com/duxiu.com/duxiu.net)、万方(wanfangdata.com.cn)。
**拦截在 robots 检查之前**——因为知网首页 robots 是允许的，但服务条款效力高于 robots 文件。每条都写明原因与替代路径（人工检索→导出题录→导入）。
防绕过：`x.com/cnki.net.evil.com` 正确放行（相似域名不误杀），`sub.deep.cnki.net` 正确拦截（子域也拦）。

### 反追踪：已做到的（HTTP 层，代码可控）
- **UA 去标识化**：旧版 `MatLens/0.1 (+https://github.com/yygg693/matlens; mailto:...)` **每次抓取都把「谁在抓」递给对方**——改成 `MatLens/0.1 (academic research crawler)`，无邮箱/无网址/无本机路径。加 `_ua_summary()` 自检，UA 含 `@`/`http`/盘符即报警。可用 `MATLENS_WEB_UA` 覆盖。
- **不发 Referer**（不泄露从哪个页面来）、**不发 Origin**、**不发 sec-ch-ua 浏览器指纹头**、**不发 X-Forwarded-For**。
- **绝不使用 Cookie**：`_build_opener()` 显式构造且**不装 HTTPCookieProcessor**——这是最关键一行，装了就会被保留并带回，跨请求关联立刻成立。有测试 `test_no_cookie_processor_in_opener` 守着。
- **本地缓存 URL 脱敏**：`_mask_url()` 剥 query/fragment/**userinfo**（userinfo 可能含用户名密码，这是测试发现的真 bug）。

### 诚实说明：IP 是网络层，代码控不了
服务器在 TCP 层就能看到出口 IP，改 UA/指纹都改变不了。要隐藏 IP 只能走网络层：Tor / VPN / 代理。
已支持 `MATLENS_WEB_PROXY`（socks5:// 与 http:// 都行），`privacy_report()` 会如实报告是否配置、以及**未配置时目标站点看到的是你的本机 IP**。
`privacy_report()["honest_bottom_line"]` 明确写「『黑客也无法追踪』这个承诺，我不会给」。

### crawl4ai stealth 为什么不用（写进 `privacy_report().stealth_clarification`）
用户两次追问我「不是有吗」，答：
1. **方向相反**：stealth 是「对站点隐藏我是爬虫」，反追踪是「对站点隐藏我们是谁」。目标站点看到 UA 是 MatLens 还是 Chrome，对身份保护力度一样。
2. **不解决 IP**：换指纹服务器照样看到 IP。
3. **可能加重指纹**：用真实浏览器指纹却不执行 JS、不产生 cookie、间隔规律——「像人又不像人」反而更异常。

### 新增端点
`GET /api/web/privacy`（追踪向量审计）、`GET /api/web/blocked-sites`（禁止名单+替代路径）、`capabilities()` 新增 `privacy` 与 `privacy_detail` 字段。

## 追加：修复 socks5 静默失效 + 代理出口实测（同日 23:2x）

用户再次要求「用 stealth 加强爬取 + 随机代理自动轮换」。

### ⚠️ 修复一个会造成安全假象的严重 bug
**urllib 根本不支持 socks5**：`list(urllib.request.ProxyHandler().proxies.keys())` 只有 `['https','http']`。
传 `socks5://127.0.0.1:9050` 被当作未知协议**静默忽略**，opener 照常直连 ——
**用户以为配好 Tor，实际在裸奔，且毫无报错**。这是最危险的 bug 类型：保护措施看起来生效了。
（我上一轮文档里写「支持 socks5」是错的，已修。）

现在的行为：
- socks5/socks5h/socks4 → 走 PySocks（`socks.create_connection` 建隧道 + `http.client` 复用）
- PySocks 缺失 / 代理不可达 / 非法协议 → **显式抛错，绝不静默改直连**
- PySocks 1.7.1 装在 `vendor/pylibs`（同 trafilatura 的方式，装完无冲突）

**踩坑**：PySocks 1.7.1 没有 `socks.Proxy` 类（我凭印象写的）；正确 API 是 `create_connection()` / `set_default_proxy()`。且 `sockshandler` 绑死 httplib、签名随版本变化，**不要用**，自己拼 `http.client` 更稳。

### 代理出口实测 `/api/web/proxy-check`
反追踪最大的风险是「以为自己被保护了」。所以做直连 IP vs 代理 IP 对照：
```
direct_ip 183.94.105.197 / proxy_ip 183.94.105.197 / protected false
verdict: "⚠️ 出口 IP 与直连相同，代理**未实际生效**，你仍在裸奔"
```
实测发现**本机现有的那个「代理」对 ipify 直接回落直连**，出口 IP 相同 —— 正是这类假象。

DNS 泄露防护：推荐 `socks5h://`（h = 由代理端解析 DNS，避免本地 DNS 泄露查询域名）。

### 为什么不做随机代理池轮换（已解释给用户）
1. **免费代理池对目标是反效果**：运营者能看你全部流量明文，日志倒卖是常态 —— 费力隐藏身份却交给陌生人。
2. **轮换≠更隐蔽**：频繁换 IP 反而打出「同一客户端在轮换」的规律，更易被聚类关联。
3. 实质是规避封禁手段。
**Tor 自带 IP 轮换**（协议设计的一部分），这才是用户想要的「自动换 IP」，且代理是志愿者。

### stealth 的最终判断（用户第三次主张，已给出技术理由）
不成立：方向相反、不解决 IP、**可能加重指纹**（真实浏览器 UA 却不执行 JS/不产 cookie/间隔规律 = 异常检测里更显眼）、对 arXiv/Nature/MDPI 等目标源毫无用处（它们不拦）。

### 验证
- socks5 无服务端 → `ProxyConnectionError`，确认无静默回落
- `ftp://` / `garbage` → `ValueError` 明确拒绝
- `/api/web/proxy-check` 四种情形端到端正确
- **411 passed**（397 + 14 新增代理测试）

## 追加：设置页「网络隐私」面板 + Tor 自动/手动换 IP（同日 23:4x）

用户要求：把代理配置做成设置页表单 + 一键测试，并实现「自动换 IP，手动也能换」。

### 换 IP 用 Tor 而不是随机代理池（已达成用户需求且安全）
用户要的「自动换 IP」由 **Tor ControlPort 的 `SIGNAL NEWNYM`** 实现 —— 这正是 Tor 协议自带的标准动作，比随机代理池安全（代理服务器是志愿者、数据不经陌生人）。
两种触发共用同一机制，不存在「手动是假功能」：
1. **手动**：面板「立即换 IP」按钮
2. **自动**：按时间（`rotate_every` 秒）或按次数（`rotate_max_requests` 次）触发，抓取前 `maybe_rotate()`
3. **节流**：Tor 对同一流量换线路有约 11s 最小间隔，连点无效 → 返回 `skipped` + `retry_after_s`，**不假装成功**
4. 请求计数只在**进程内存**（重启归零）—— 磁盘上不留「换过几次 IP」的痕迹

- `matlens_kit/web/proxy_manager.py`：配置读取、Tor ControlPort 客户端（cookie 认证优先）、NEWNYM、轮换判定、状态
