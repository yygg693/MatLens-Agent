## 修复既存 bug：两份 config.yaml 导致设置「保存成功但读不回来」

用户批准修复上一轮发现的问题。

### 根因
`matlens_kit/settings_store.py::_home()` 硬编码 `Path.home()/".matlens"`，
而 `matlens_cli.config.get_matlens_home()` 是平台原生路径（Windows 上
`%LOCALAPPDATA%/matlens`）。两者指向**不同文件**：
- `update_settings` 复用 `matlens_cli.config.save_config` → 写 AppData
- `load_settings` 走 `_read_raw_config` → 读 `~/.matlens`
→ 结果：写入成功但读回默认值，**静默数据丢失**。

`get_matlens_home()` 的 docstring 明写 *"This is the single source of truth — all other copies should import this."* —— 是 settings_store 没遵守。

### 实测状态（修复前）
- `~/.matlens/config.yaml` = 5045 字节 / **26 段**（真实主配置）
- `AppData/Local/matlens/config.yaml` = 2142 字节 / **3 段**（本轮测试写入所致）

### 修复方案（最小改动）
1. `_home()` 改为直接调 `get_matlens_home()`，并保留 env 兜底。
2. 新增 `_legacy_home()` 与 `_config_candidates()`：读时**两个路径都读**，
   权威路径已有值不被旧路径覆盖（`setdefault` 语义）。写时只写权威路径。
   兼容理由：项目里大量模块（server.py / graph_api / experiment_api 等）
   硬编码 `~/.matlens`，它们的产物仍落那里。
3. `_read_raw_config()` 改为多路径深合并。
4. ⚠️ **设了 `MATLENS_HOME` 时不读旧路径** —— 那正是测试隔离
   （`tmp_mat_home` fixture）与多 profile 约定，混入真实用户目录会让测试随机失败。

### 配置迁移
脚本 `scripts/migrate_config.py`（幂等、自动备份）：
- 权威文件不存在 → 整份复制
- 已存在 → 逐段深合并（权威值优先）
- 实测：3 段 → **27 段**，丢失段数 **0**
- 备份在 `_backup_config/`（迁移前后各两份，共 4 个）

### 修完后验证
- 写入 `max_turns=321` → 读回 321（此前坏的路径）
- 原有设置完整：theme=dark / reasoning_effort=high / max_turns=500 /
  kb 5 字段 / papers 6 字段 / memory 4 字段
- **429 passed**（425 + 4）

### 测试修复（暴露出的隔离问题，非产品 bug）
路径统一后能读到用户真实配置，4 个旧测试因此失败 —— 它们假设「无配置」：
1. `test_defaults_shape` 断言 `max_turns == 25`，但用户实设为 500 → 拆出
   `test_defaults_are_used_when_no_disk_config`（用 tmp_path 隔离 + monkeypatch
   `_config_candidates`）
2. `test_get_shape_and_old_fields` 同理
3. `test_agent_reset_triggers` / `test_reset_restores_defaults` 同根因
4. 新增 `test_read_raw_merges_legacy_path`（验证合并语义）
5. 新增 `test_legacy_path_skipped_when_home_overridden`（守住测试隔离）
6. 新增 `test_home_uses_authoritative_source`

**教训**：断言「默认值」的测试必须隔离磁盘配置，否则用户改过值就随机失败。

### 连带清理

现 bug 已修 → 回到单一来源，避免路径逻辑再次分叉。

## ⚠️ 纠正 + 彻底收拢（10-16 上午）

用户说「一起收拢」那批硬编码路径。**动手前实测发现我上一轮判断错了，必须纠正。**

### 我上轮的误判
昨天认定「`~/.matlens` 是待迁移的旧目录，权威是 AppData」—— **反了**。
实测数据：
| 项 | ~/.matlens（我以为的旧目录） | AppData（我以为的权威） |
|---|---|---|
| state.db | **15 MB** | 448 KB（停在 8/26） |
| sessions | **9.1 MB** | 0 |
| provider_models_cache | 14 KB | 1.3 KB |
| config.yaml 段数 | 26（真实） | 27（我迁移产物） |

`~/.matlens` 才是真正在用的目录，AppData 那份是我**测试脚本裸跑**时用
`matlens_cli` 写出来的副产物。好在没造成损失：真实配置一直没丢。

### 真正的根因
`matlens_constants._get_platform_default_matlens_home()` 在 Windows 上返回
`%LOCALAPPDATA%/matlens`，而项目里 **30+ 处硬编码 `~/.matlens`**
（server.py / graph_api / experiment_api / kanban_db …）。
服务进程靠 `matlens_kit/api/__init__.py` 的
`os.environ.setdefault("MATLENS_HOME", "~/.matlens")` 兜住 → 落 `~/.matlens`；
**裸跑脚本无此兜底 → 落 AppData**。
→ 表现为「设置保存了却没生效」「数据不见了」，且只在裸跑时发生，极难察觉。

### 修法（一处改动，全项目生效）
改 `_get_platform_default_matlens_home()`：Windows 也返回 `~/.matlens`，
与项目既有行为对齐。于是无论是否经过服务进程，解析结果都一致。
需要多 profile 时用 `MATLENS_HOME` 或 `set_matlens_home_override()` 显式指定。

### 数据清理
- 逐字段比对两份 config：**除我新增的 network 段外零差异**（0 个差异字段）
- 只把 network 段补进真实配置（26 → 27 段）
- network 段的 `proxy_enabled/rotate_enabled` **置为 false**（我没装 Tor，
  开着会导致抓取全部失败）
- 备份陈旧目录 → `_backup_config/appdata-stale-20261016-085557`（713 项）后删除

### 代码简化
根因消除后，`settings_store` 的双路径兼容读取已成冗余 → 退回单路径
（`_config_candidates()` 只返回 1 个）。**路径一旦多源，就会再次分叉出
「保存成功却读不回来」这类静默问题。**

### 测试
- 删掉测「双路径合并」的两个测试（行为已移除）
- 新增 `test_config_path_is_single_source`（守护单路径）
- 新增 `test_platform_default_matches_legacy_hardcoded_path`
  （**关键防回归**：默认 home 必须与硬编码一致，变了就报并指出影响面）
- 新增 `test_bare_import_resolves_same_as_server`（子进程实测裸跑 vs 服务一致）

**教训**：修「路径分叉」类 bug 前，必须先比对两边的**真实数据量**（文件大小、
mtime），而不是只看代码。差点把 15MB 真实数据当成"旧目录"迁走。

### 验证
服务读到真实设置（max_turns=500 / high / dark）、写入读回闭环、知识库
demo-kb 与 graph.json 均在 `~/.matlens`、代理开关已关。**432 passed**。

## 修复对话框加号菜单：工具与技能「显示乱 + 不能用」

用户先报「加号里有些功能用不了」，随后补充关键症状：
**弹出来的工具列表排版混乱，且不能点击使用（希望能把命令发到对话框）**。

### 诊断（两轮，第一轮我测错了）
第一轮我只验证了「弹窗是否打开」→ 结论"功能正常"，**这是错的**。
教训：验证 UI 要验证**实际效果**而非元素是否出现。

第二轮实测发现：
1. **排版乱的根因**：`.tc-item` / `.tc-ic` / `.tc-info` / `.tc-name` / `.tc-desc`
   这些 CSS **根本没定义**（只有 `.tc-sec-title` 有），所以图标塌成一列字母、
   名称与描述挤成一行。
2. **不能用的根因**：弹窗只输出 `<div class="tc-item">` 纯展示，
   **没有任何 click 事件**；且即使能点，详情抽屉里也只有「参数表 + 复制工具名」，
   用户必须手动把参数敲进对话框 —— 这才是「工具不能真正用起来」的根因。

### 修法
1. **补全 CSS**（`.tc-item` 等）+ 卡片式布局：图标 / 名称+mono 工具名 /
   两行截断描述 / 分类与参数数标签 / hover「打开 ›」。
2. **条目可点**：事件委托 `.tc-item` → 按 `data-kind` + `data-name` 从当前
   已加载数据里查找（不重新请求）→ 关目录 → 开详情抽屉。
3. **抽屉加填参表单** `_formHtml()`：按 `params_detail` 生成 input/textarea，
   标必填、`examples` 提供「用示例值」一键填充。
4. **新增「发送到对话框」** `_sendToChat()`：收集参数（能 parse 成 JSON 就
   转，否则当字符串；空的可选参数不带）→ 填入输入框 + `dataset.toolPayload`
   存结构化数据 + 聚焦 + toast 提示。**只填不自动发**，让用户确认后再 Enter。
5. 参数 schema 表与示例改为 `<details>` 折叠（表单已含字段说明，原样平铺是冗余）。
6. **顺带修真 bug**：抽屉头部是 HTML 静态块（写死「工具详情 / 点击左侧任意卡片」），
   而 `_drawerHtml()` 又渲染一份真标题 → 顶部永远显示死文案、真标题挤在半截。
   改为固定头部 + `_syncDrawerHead(t)` 动态填，关闭时复位。

**知网 RefWorks 三个坑（全部实测踩过）**：
1. `%A 张伟%0 李明%0 王芳` —— `%0` 既是类型标记又是多条分隔符
2. `%0` 后跟的是**数字 0**；正则若写 `%([A-Za-z])` 则**永不匹配类型行** →
   多记录被并成一条（实测本该 2 条只出 1 条）
3. DOI 藏在 `%R` 里且可能是 `doi.org` URL 形式

端点：`POST /api/kb/{name}/import-citations`（按 DOI 去重）+ `POST /api/kb/citations/preview`。
另修：`.txt` 无条件兜底成 refworks 会把普通文档误判为题录（改为「有 %T/%A 标签才算」）。
